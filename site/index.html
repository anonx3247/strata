01

Types as contracts

Types carry constraints, and functions say what they need and what they promise. Both are part of the signature, and both are checked wherever the code is used.

See it in the tour →
02

Proving over testing

An SMT solver proves each contract for every input, or finds the input that breaks it. A fuzzer covers what it can't prove. Most tests become a line in a signature.

See it in the tour →
03

The code is the AST

Code is stored as its syntax tree. Text is rendered when someone wants to read it, and edits are parsed back in, so diffs, merges and views work on definitions instead of lines.
