Strata

An experimental programming language where code is a tree of definitions, constraints live in the types, contracts are proven, and every edit is checked against the whole codebase before it is committed.

scroll
The problem

Agents write code faster than anyone can read it.

The tools around code were built for people reading text: line diffs, tests someone remembered to write, grep to find who calls what. With agents making most of the changes, each of them hides what matters.

01 · DIFFS

A rename is a wall of red and green

Renaming one variant: 14 changed lines across five definitions. Whether a change renames, re-wraps, or breaks a contract, you have to work out by reading.

Changes are structural: "renamed Shipped → Sent".
see it ↓
02 · TESTS

Tests check the cases someone thought of

Every test passes, and the bug lives in the input nobody tried. An agent's tests share its blind spots.

Say what must hold. The solver checks every input.
see it ↓
03 · CONTRACTS

Tighten a function, break a caller far away

A stricter precondition is one added line. Nothing tells you which callers relied on the old one.

Dependents are re-checked against the new contract.
see it ↓
04 · EDITS

A broken edit lands, and someone finds out later

Text accepts anything. The breakage shows up in CI, in review, or in production.

An edit that doesn't check is refused; a breaking one becomes holes.
see it ↓

Fix 02 · Proven, not just tested

Every test passed. The bug was still there.

An agent fills in a refund policy: what was paid, minus a 5.00 handling fee. It writes a test, as a careful agent would. The test passes. But the signature already said what must hold, for every order: ensures it >= 0. Strata checks that, not just the cases someone wrote down.

What the verifier says, and how sure it is

The same check on a tour of number functions (examples/math.strata). Each verdict says which it is: ✓ proven by the solver for every input, ~ fuzzed where it couldn't prove it, ✗ refuted with the input that breaks it. Termination is shown too, or flagged: nobody knows whether Collatz ends.

No test was written for next_digit or average. Their types and contracts were enough to find the bugs.

$ strata verify

Many agents, one codebase

Two agents touch the same function. Nothing conflicts.

On main, agent A renames line_total to line_cost. On a branch, agent B rewrites its body. As text, the two changes overlap. Strata's merge driver pairs definitions, applies A's rename to B's code, and checks the result before committing it.

Definitions, not files

Text is just a view. Ask for the detail you need.

Each definition is a syntax tree with a content hash. An agent asks for the slice it is working on, slice:Order here: Order, what it uses and what uses it, at the level of detail the task needs. What it sends back with strata edit is checked against everything else.
