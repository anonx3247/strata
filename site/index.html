What Strata changes for agents

Agents write code fast. Strata makes what they write checkable.

Contract-based programming

Today, an agent shows its code works with tests: many of them, kept apart from the code, covering the cases it thought of. In Strata, a contract is proven for every input, so there are fewer tests to write and fewer bugs that get through.

Contracts

Constraints on types, promises on functions.

A Cents is never negative, a Percent stays between 0 and 100. requires says what a caller must guarantee, ensures what the result keeps. The solver checks both sides: sale calls discount with a price it doesn't accept.

For an agent: what a function needs and promises is in its signature, so it can use code it hasn't read.

Laws

A trait says what it means.

A law is a property of several calls together, stated once on the trait: a transfer neither makes nor loses money, and one that fails leaves nothing half done. Every implementation of Ledger, in memory or over a database, is proven against them.

For an agent: a backend it writes is checked against what the trait means, not only against its method types.

Fewer tests

Four tests, or one line.

Tests check the values someone thought of. One ensures says the same for every input, and the solver proves it. Where it can't, a fuzzer runs the function against the contract, and the verdict says which of the two it was.

For an agent: less to write and maintain, and every input covered, not only the ones it tried.

Editing the syntax tree, not text

Today, an agent edits lines in text files: it searches its way around, breaks code in files it never opened, and hands over diffs nobody can read. In Strata, code is stored as its syntax tree: the program always type-checks, even unfinished, and a change reads as what it is.

Always checked

Unfinished code still checks.

In this order system, refund isn't written yet: its body is a hole, ?refund_policy, and everything around it still type-checks and verifies. strata holes gives the task: the type to produce, what is in scope, the contract to meet. Each edit is checked against everything it touches before it is stored; one that doesn't check is refused.

For an agent: a precise task to fill, and no broken state to dig out of.

Structural diffs

A rename reads as a rename.

Changes are made to definitions, so a diff lists what happened to them, not the lines that moved.

For an agent: its work can be reviewed by reading what changed, not hundreds of lines of noise.

Less noise

Only what it needs.

An agent asks for the part of the code it needs, at the detail it needs: a map of what uses what, the interfaces with their contracts, or the source. Every view is rendered from the same trees.

For an agent: no searching through files to find its way, and less to read before it can start.
