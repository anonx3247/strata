## `core`

What every program has without a `use` is declared in `core/`, a package below the standard library that depends on nothing (std depends on it): `core.types` (the types below, `Debug`, `Display`, `Option`, `Result`, the refinements), `core.builtins` (the builtin functions), and code modules a program gets only when it uses them: `core.iter` (iterators, when it names one of theirs: `xs.iter()`, `impl Iterator`, ...; a list's `map` is a builtin and needs none), `core.channel` (`channel()`, `Sender`, `Receiver` and their methods), `core.text` (`s.bytes()`, `s.code_points()`) and `core.task` (`Panic`, for `supervised spawn`). `core.mem` is raw memory (`Ptr`, `raw_alloc`, `load_i64`, `store_u8`, `atomic_add_i64`, ..., on machine integers), what the runtime is written in: only core's own modules can use it (anywhere else, `Ptr` and its functions are errors). `core.rt` is the runtime written in Strata: the allocator and reference counting (`strata_alloc`, `strata_dup`, `strata_release`, `strata_free`), so nothing in its functions may allocate (the checker refuses lists, records and closures made at run time, `Int` arithmetic, and calls to anything but core.rt's, core.mem's and the integer conversions). `strata --file core test` runs core's own tests. What the compiler itself provides is declared with `builtin`, which only `core` may use: a type with its parameters (`builtin type Dict[K, V]`) and a function's signature, with `requires` where it fails on some arguments, so a builtin's precondition is a contract like any other, and one without `requires` always returns:

```rust
/// `xs[i]`: element `i`, from 0.
builtin fn at[A](xs: List[A], i: Int) -> A
  requires 0 <= i && i < len(xs)

/// The string of one character, code point `c` (not a surrogate).
builtin fn chr(c: Int) -> String
  requires 0 <= c && c <= 1114111 && !(55296 <= c && c <= 57343)
```

A name may have several signatures (`len` of a list, a dict or a set): the first whose parameters fit the arguments is called. `strata --file core render builtins` shows them all (`strata builtins` lists them in short); `strata --file core/ edit MODULE < text` stores a module of core as written (its names are global, nobody's module's), and `strata --file core check` checks the core strata is built with. Not yet contracts: `matches` with a pattern that isn't a regular expression, and a channel used after it ended.

## Compiling

`--strata` and `--compare` run the front end and code generator written in Strata (the repository's `compiler/` program) in place of, or next to, the Rust ones, on the commands it implements: `check` (`compiler check`; a script or a package, its modules checked together), `lex` and `parse` (`compiler lex`, `parse`, and `stored` for `parse --stored`), `render` (`compiler written`: the stored tree written back with names as short as the module's imports allow, then printed; a whole script or each module of a package), `run` (`compiler eval`: `main` gets the arguments after `--`, else `one` and `two words` as the tests give them, its options read by the derived `CommandLine` (std.cli) as a compiled program reads them, `--help` and bad arguments ending it the same way, and a `Disk` that reads files; writing files isn't run, since `--compare` would do it twice) and `build` (`compiler codegen`, linked with `src/llvm/runtime.c` by clang; a script or a package without dependencies, with the std modules it uses; for a script, the checks `verify` proved are left out as `build` leaves them out). `--strata` prints the Strata implementation's output alone (`build --strata` writes the executable); `--compare` runs both and prints the lines only one of them gives (`only in rust: …`, `only in strata: …`; for `check` the errors, for `build` the two programs' stdout, stderr and exit code), exit 0 when they agree, 1 when not. On a package, `lex` and `parse` take each module's text (as `render` writes it), `render` each module file (std's named `std.io`, …), `run` the program packed into one bundle (`strata pack`); their lines are prefixed with the module's name. Where the Strata side doesn't cover a case (a program `compiler/codegen` can't compile yet), it says so and exits 2. The compiler package is the `compiler/` folder of the repository `strata` runs in (in the current folder or above, or above the `strata` executable; `STRATA_COMPILER=DIR` names another), built once with `strata build` into `~/.cache/strata/compiler/<hash>` (`STRATA_CACHE`) and rebuilt when it, `std/` or `strata` changes; without it, the flags say so and exit 2. `verify` has no Strata implementation yet. `lex` and `parse` are the Strata side's by default (`--rust` runs the Rust lexer and parser, the reference the tests compare against; without a compiler package they fall back to Rust), and so are `render` of a whole script without a view's options, `run` of a program's `main` (`run [PATH] [-- ARGS]`, no `--trace`), and the code `build` and `test` generate (see [Compiling to native code](tools.md#compiling-to-native-code)); `--rust` runs Rust's, and what the Strata side doesn't cover (a package's module, `--split`, `--level`, `--members`, one function called, a program the evaluator stops on, such as `select`, `race` or writing files) is Rust's.

`strata build` compiles a program to an executable through LLVM: it writes LLVM IR as text, and `clang` compiles it with a small C runtime (`STRATA_CC` chooses another compiler). `--emit-llvm` prints the IR instead. Two code generators write that IR. By default it is `compiler/codegen`, the one written in Strata (for `strata test`, with `--file`); where it doesn't cover a program yet, `build` says so (`note: …; using llvm.rs`) and the Rust one, `src/llvm.rs`, compiles it. `--rust` (or `STRATA_BACKEND=rust`) asks for the Rust one, which also builds `--emit-llvm`, `test --with-deps` and the compiler package itself (building it with `compiler/codegen` would need it built first). The first build after a change to `compiler/` or `std/` rebuilds the compiler package (about 2 minutes, then cached).

Programs are compiled unoptimized (`-O0`), which is fastest to build; `--release` compiles at `-O2` and merges the runtime into the executable (`-flto`). `run` and `test` take `--release` too. Compile-time code and the probes that confirm counterexamples are always unoptimized (they run once), `verify`'s fuzzing always optimized (its cases run many times), and std's precompiled library is built once at `-O2`.

The runtime is C (`src/llvm/runtime.c`) but for `core.rt`, written in Strata: the memory allocator (`strata_alloc`, `strata_dup`, `strata_release`, `strata_free`) and `strata_unique`. `strata build-core` compiles it to LLVM IR with the C runtime's names, every executable links it, and strata itself is built in two stages to use it (`tools/bootstrap.sh`, see `core/rt.strata` in [the source layout](#source-layout)). `build` first verifies what changed since it was last verified (`--no-verify` doesn't), and the checks proven are left out of the program (`--all-checks` keeps them; see [verification](verification.md#what-is-proven-isnt-checked-again)).

A compiled program behaves as `strata run`: the same output, and contracts are checked at run time with the same fault messages (refinements of parameters, results, annotated bindings, declared variables and new values, `requires`, `ensures`, `assert`), exiting with 101. The language compiles (there is no interpreter), but for a few methods called on a value of a trait type (one taking `Self` inside another type, such as `List[Self]`, or type parameters together with `Self` or `mut`), which are refused saying so. In particular:

- `Int`, which never overflows: one in [-2^62, 2^62) is a machine integer, and arithmetic on it stays inline; any other is a big integer in the runtime (kept in the 64-bit values outside that range, so comparing a small and a big integer needs no call). `Float`, `Bool`, `String`, `()`, and refinements of them;
- records, variants (`Option`, `Result` and your own), tuples, `distinct` types, unions of any types; field access, `{ ..e, f: x }`, assigning a field (`x.a.b = e`), `is`, `==` on any of them, and printing them as code (`Debug` / `Display`);
- generic functions and types (each compiled once per set of type arguments), a type's own methods (`impl Item { ... }`), and traits: implementations chosen from the type where the call is compiled (default methods, supertraits, generic traits and implementations, static methods like `T.empty()`, a variant's own implementation chosen by its tag), with the trait's `requires` and `ensures` on every implementation;
- lists: literals, `+`, list patterns (`[x, ..rest]`), `for` over a list, `xs[i]` and slices (`xs[1..]`), and the list built-ins (`len`, `get`, `at`, `slice`, `push`, `take`, `drop`, `range`, `map`, `filter`, `fold`, `all`, `any`, `find`, `count`, `contains`, `reverse`, `sort`, `sort_by`, `zip`, `enumerate`, `sum`, `join`), most of them written in Strata (`src/llvm/prelude.strata`);
- dictionaries and sets: literals (`Dict { "a": 1 }`, `Set { 1, 2 }`, typed empty ones), `dict`, `set`, `insert`, `remove`, `get`, `contains`, `keys`, `values`, `items`, `map_values`, `to_list`, `union`, `intersection`, `difference`, `len`, `for` over them (a dictionary gives `(key, value)` pairs), `==`, printing (`Debug` / `Display`), and the refinements of their elements, keys and values. Each is a list kept in the order on values (a set's elements, a dictionary's pairs by key), so equal collections are equal lists; their built-ins are Strata over lists, given the order of the element type;
- strings: `+`, comparisons, a string's units (`bytes()`, `code_points()`, `graphemes()`) and positions as byte offsets (`byte_len`, `byte_slice`, `index_of`), and the string built-ins (`split`, `lines`, `trim`, `contains`, `starts_with`, `ends_with`, `replace`, `repeat`, `reverse`, `chars`, `to_upper`, `to_lower`, `is_digit`, `is_alpha`, `is_space`, `ord`, `chr`, `parse_int`, `parse_float`); most of them are Strata in the prelude over `byte_len` / `byte_at` / `byte_slice`, the rest (`trim`, case mappings, the `is_` tests, parsing numbers) C in the runtime, case mappings and `is_alpha` from tables made from Rust's;
- iterators (`for` over any `Iterator`, lazy `map` / `filter`, `iter()`), tasks (`scope`, `spawn`, `await`, a thread per task), channels and `select`, written `invariant`s (checked at the loop's head), and `extern c` calls;
- lambdas and closures, named functions as values (`filter(is_prime)`), functions returning functions;
- functions and recursion, bindings (`x := e`, with patterns, `let x: T = e`), `mut` variables and assignment (`=`, `+=`, …), `if`, `match` with every pattern, `while`, `loop`, `for`, `break`, `continue`, `return`, `assert`, `!`, `?`, `except`;
- f-strings with format specs (`{x:.2}`, `{n:>5}`, `{n:05}`, `{s:*^9}`), and `print`, `to_string`, `abs`, `min`, `max`, `float`, `floor`, `ceil`, `round`, `sqrt`;
- `mut` parameters and receivers (`restock(mut line.qty, 5)`, `mut console.print(s)`): the function changes the caller's variable in place, and the variable's declared type is checked after the call;
- capabilities: `main` can ask for `Console` (std.io) and capabilities such as `Disk`, `Process` and `Codebase` (std.fs, std.process, std.code), and gets the terminal, the disk, the process and the codebase in the current folder, as with `strata run` (the program's arguments too). `Codebase`'s snapshot is built by strata and written into the program's memory, so a program built with `strata build` has none (it faults saying so). A parameter whose type is a trait (`console: Console`) is compiled once per implementation passed to it, as the language defines it (`console: C` for some `C: Console`): the real console and a `Recorder` in a test each get their own. A trait used as the type of a field, a list element or a `let` (`{ console: Console }`, `List[Shape]`) holds any implementation: the value carries its implementation's table of methods, and calls go through it;
- options: `main` can ask for a record that derives `CommandLine` (std.cli); the compiled program reads it with the same `from_args`, so `--help` and the messages for bad arguments are `strata run`'s (exit code 0 after the help, 2 after an error). The usage line names the executable as it was started (`strata build` names it after the package, as `strata run` does);
- `main` returns `()`, an exit code, or a `Result` of either.

A fault prints the call stack as `strata run` does (`    stack: main -> inner -> half`), and running out of stack is a fault (`fault (Limit): stack overflow (recursion too deep)`), not a crash. There is no other limit: loops run as long as they run, and a recursion as deep as the stack allows; the `stack:` line shows a recursion as one entry (`main -> down (95846 times)`).

`matches(s, re)` is `std.regex`'s, compiled. A literal pattern's matcher (`std.regex.matcher`: a DFA, or the Pike VM's program when the pattern asserts more than `^` and `$`) is made while compiling, as compile-time code is (cached), and is data in the program. A pattern built at run time is matched by `std.regex` (its parser and Pike VM, written in Strata and precompiled with std), in a built program too; a bad one faults with `std.regex`'s message (`bad regex: unclosed group (at character 11)`). Memory is reference-counted: a value is freed as soon as nothing holds it. With `STRATA_MEMORY` set, a compiled program reports how many objects it allocated and freed when it exits (`memory: 128 allocated, 128 freed, 0 live`); with `STRATA_MEMORY=check` it also keeps freed memory aside, stops on any use of a freed object (`memory: drop of a freed object`), and lists the objects still alive at the end (the tests of `strata build` run every program this way).

### The JIT

`strata verify` runs only compiled code (`--jit` says why a function's fuzzer couldn't be compiled, which is then skipped). Fuzzing: a driver per function generates its arguments (the generators `mock` uses), records them for a counterexample, and calls it, all in one module compiled once; a trait method of an implementation, and a law, are fuzzed through a wrapper function (a law's ensures it holds). Loops and calls count steps, so a runaway case is a `Limit` fault (`too many steps`). The solver's counterexamples are confirmed by running them compiled (a probe binding the values to the parameters' types, then calling the function), and so are literal arguments that break a refinement (`attr("onclick", …)`), an error before anything runs. Probes, like compile-time code, are compiled without optimization: they run once.

`strata test` compiles the tests the same way: each `test` block is a function, a fault ends the test instead of the process, and what a test prints is kept for the report (`strata test --emit-llvm` prints the tests' IR). A test that can't be compiled yet fails, saying why; the others run. Only the project's own tests run, those in its files (the package's, or the script's): what it imports (std, and dependencies once they are fetched) is compiled, verified and tested on its own (std with `strata --file std test`), so its tests aren't run again. `strata test --with-deps` runs them too.

`strata run` compiles the same IR in memory with LLVM's libraries and runs it (the JIT), so a program runs at native speed without a build step (`fib(32)`: 26 ms, compilation included). What can't be compiled yet is an error that says why (there is no interpreter). `strata run f [ARGS]` calls one function, compiled: its arguments, written as code (`'"abc", 3'`), go into a function that calls it, checked with the program, and its result is read back from memory and printed as code, and `--trace` has compiled code print each call and return. Compile-time code runs on the JIT too: in a `derive`, and `comptime e` anywhere else, whose value is computed while compiling and written into the program as a constant (`re := comptime parse("[a-z]+")` never calls `parse` when the program runs). `e` may use definitions, not the variables around it.

Both ways share one code generator (the IR as text, which LLVM parses for the JIT) and one runtime (`runtime.c`, built into `strata` for the JIT, compiled with the program by `strata build`).

## The compiler in Strata (`compiler/`)

The compiler written in Strata is the `compiler/` package: an ordinary package (its modules named by their paths: `lex`, `parse`, …), a program rather than a library, and not part of std. Its `main` (`main.strata`) runs one step on files, a command each (`tree`, `same`, `hashes`, `text`, `bad`, `lex`, `parse`, `stored`, `stored-package`, `written`, `use-errors`, `check`, `eval`, `instantiated`, `builtins`, `codegen`, `jit`, `smt`, `termination`, `package`, `update`), printing what the Rust side prints; the tests build it once (`strata build compiler`, `tests/common/compiler.rs`) and compare. `check` and `package` load std lazily (`std_imports`): from the std names the definitions are written with (`binary.decl_strings`, their string tables) it follows std's header entries (each lists what its definition refers to) and decodes only the definitions reached (`binary.decode_entry`), with the impls whose type and trait are in (nothing names an impl) and, for a name that is no definition (a variant, a trait method), its module's types and traits.

| `walk.strata`, `desugar.strata`, `derive.strata` | rewriting a tree one level at a time; ranges, indexing, slices and comprehensions turned into calls of built-ins once a program is read (`src/desugar.rs`); derived traits and compile-time code (`src/derive.rs`), so nothing that checks, runs or compiles code sees them |
| `deps.strata` | packages' `[deps]`: path and git dependencies, their modules named with the package as prefix, `strata.lock`, no package cycles |
| `codegen.strata`, `unicode.strata`, `c/jit.c` | the code generator: a program as LLVM IR (text), as `src/llvm.rs` writes it, for the same runtime; `strata build` and `strata test --file` use it by default, compared with `llvm.rs` by `tests/codegen.rs` (same output, not the same IR). `unicode` is the case-mapping tables it emits (generated by `tools/codegen_unicode.rs`); `c/jit.c` runs its IR in memory through LLVM's C library (`compiler jit`) |
| `smt.strata`, `termination.strata` | the verifier, being ported: the SMT encoding of a function's obligations (`compiler smt`, compared with `strata verify --obligations`), and the termination analysis (`compiler termination`, compared with `verify --termination`); `verify` itself is still Rust's |

### Module by module

The **compiler written in Strata** is the `compiler/` package: a program, not part of std (programs don't import it). Its `main` runs one step of the front end on files (`strata --file compiler run -- lex FILE`, `parse`, `stored`, `check`, `eval`, …: see `compiler/main.strata`), and the tests compare what it prints with the Rust front end. Its modules:

| Module | What it has |
|---|---|
| `ast` | Strata's syntax tree as Strata types (`Decl`, `DeclKind`, `TypeExpr`, `Expr`, `Stmt`, `Pattern`, …), node for node as the compiler's |
| `binary` | `.strata` files read and written in Strata: `read(bytes)` (a module file or a bundle), `read_header`, `decode_module` (checking each definition's hash), `decode_definition`, `encode_definition` (a definition's bytes, exactly as strata writes them), `hash` / `interface_hash` / `code_hash`; `without_notes` (in `ast`). Its SHA-256 is private: it names definitions, and std has no public hash function until one has been reviewed as cryptography |
| `text` | the printer, in Strata: code as text, laid out as `src/printer.rs` lays it out (lines broken to stay within 80 columns): `module_text(decls)` (a module file's definitions), `decl_text`, `fn_decl_text`, `type_decl_text`, `expr_text(e, depth)`, `type_text`, `pattern_text`, `block_text`, `escape`. It prints a tree as given: `strata render` first turns a stored tree into its written form (names shortened to what the imports allow), which takes name resolution |
| `lex` | the lexer, in Strata: `lex(text)` gives the tokens (`Token { tok, line, col, nl_before, space_before }`, `tok` an `IntTok`, `StrTok`, `FStrTok`, `Ident`, `Sym`, …, then `Eof`) and the `//` comments, or the error `src/lexer.rs` gives (`1:9: unterminated string`); `token_text` / `comment_text` print them as `strata lex FILE` does |
| `parse` | the parser, in Strata: `parse_module(text, module)` / `parse_program(text)` give the definitions as `src/parser.rs` parses them (comments in place), or its error (`3:5: expected `)` (found Sym(","))`); `parse_expr(text)`. The tree is as written: storing it (`strata edit`) qualifies its references, which takes name resolution |
| `resolve` | names, in Strata, as `src/resolve.rs` does them: `stored(decls, std)` gives a parsed program (a script, or a package's modules together) in its stored form (every reference to a definition by its qualified name, locals and methods as written), with std's definitions in scope; `written(decls, std)` the written form `render` shows (each reference as short as the imports allow, a union written out named, a type one union lists shown inside it); `union_members` decides a union's bare members; `errors(decls, std)` gives the resolver's errors (a `use` of what doesn't exist or is private, a private name, std's host built-ins outside std, a mock outside tests, an extern called from another module) |
| `desugar` | the sugar turned into calls, as `src/desugar.rs` does after resolution: `desugar(decls)` gives the program with `a..b` as `range`, `xs[i]` as `at`, slices as `slice`, comprehensions as `map` / `filter` / `fold`, `Dict { .. }` / `Set { .. }` as `dict` / `set`, record defaults filled in, refinements written as type arguments as aliases (`$where_0`) and unions with members of both kinds split (`Shape$own`), and the errors (a range missing an end outside a slice). `check` and `eval` work on its result |
| `walk` | rebuilding a tree one level at a time (`expr_children`, `type_children`, `decl_parts`) and collecting what is in it (`kids`, `decl_exprs`, `decl_types`, `any_expr`), for the passes that rewrite programs |
| `check` | the type checker in Strata, so far: `definition_errors` (a name defined twice, or the prelude's; two `impl Type` blocks; a trait implemented twice), `variant_errors`, `mixed_unions` (a union with members of both kinds split as the checker splits it), `expression_errors` (unknown variables, wrong numbers of arguments) and `type_errors` (inference for `Int`, `Float`, `Bool`, `String`, `()`, lists and the program's functions), each worded as `strata check` words it |
| `eval` | running a program from its stored trees, in Strata: `run(decls, args)` gives a `Run` (`stdout`, `stderr`, `code`), what the compiled program prints and its exit code, faults and their messages included. It finds methods from the receiver's type at run time, gives `main` the console and the process, and knows what a function's type parameters stand for while it runs (`T.zero()`, `Self.check(x)`, `T.from_json(j)`): from the values it is called with, the receiver's `impl`, and the types `check.instantiated` writes around generic calls (`{ $result: T := call; $result }`, the type the caller wants). `strata pack --prelude FILE` writes the prelude's definitions, which a program runs with; `world(decls)` / `value_in(w, module, e)` run one expression (what `derive` runs compile-time code with). Not yet: files, mocks, `extern` |
| `derive` | derived traits and `comptime`, as `src/derive.rs` makes them: `expand(decls)` replaces each `derive Trait for Type` by its `impl` (the type described as a `std.typing.Type` value, checked against the trait's kind and requirements; each `derived fn` specialized: `comptime e` evaluated by `eval` and written in, `comptime for` and match comprehensions written out, `match comptime` keeping the arm that fits, `make` / `try_make` built field by field, calls of functions with `comptime` parameters turned into copies) and folds every other `comptime e` into its value, with the errors (`compile_error(..)` reached, a kind that doesn't fit). `setting(..)` is `None` (no `strata.toml` read yet) |
