# Internals

## Source layout

Strata is written in Strata: the `strata` command is the `compiler/` package, built by a `strata` before it (`tools/bootstrap.sh`, a fixed point), with a small C runtime and LLVM linked in.

| File | What it is |
|---|---|
| `compiler/` | the `strata` command: the front end, the checker, the verifier, the code generator, the codebase commands and the driver, module by module below |
| `compiler/c/` | the C the compiler links in: `jit.c` (LLVM's JIT, running compiled code in memory), `ir.c` (codegen's IR text built in LLVM through its C API), `toolchain.cpp` (LLVM: IR to objects; lld: linking), `driver.c`, `cache.c`, and `libSystem.tbd` (the stub of macOS's libSystem executables link against) |
| `runtime/runtime.c` | the C runtime compiled code links with: reference counting, big integers, printing, tasks and channels, the host's I/O; `core.rt` replaces its allocator and string, integer and list functions with Strata's (`-DSTRATA_CORE_RT`) |
| `runtime/prelude.strata` | the built-ins of lists (and `keys`, `values`, `map_values` over a dictionary's entries), `lines`, and the string built-ins written over `byte_len` / `byte_at` / `byte_slice`: compiled with every program |
| `core/` | `core`: the builtin types and functions (`builtin type`, `builtin fn` with their `requires`), the types and traits every program names, the code modules (`core.iter`, `core.channel`, `core.text`, `core.task`) and raw memory (`core.mem`, only for core's own modules) and compiled values read back (`core.values`' `Raw`, for core and packages with `[values] read = true`) |

| `std/regex.strata`, `std/unicode.strata`, `std/unicode_tables.strata`, `tools/unicode_tables.py` | regular expressions in Strata: the parser and the tree (as regex-syntax's `Hir`), sets of code points, Unicode properties and case folding; the tables are generated from regex-syntax's by the script |

## `core`

What every program has without a `use` is declared in `core/`, a package below the standard library that depends on nothing (std depends on it): `core.types` (the types below, `Debug`, `Display`, `Option`, `Result`, the refinements), `core.builtins` (the builtin functions), and code modules a program gets only when it uses them: `core.iter` (iterators, when it names one of theirs: `xs.iter()`, `impl Iterator`, ...; a list's `map` is a builtin and needs none), `core.channel` (`channel()`, `Sender`, `Receiver` and their methods), `core.text` (`s.bytes()`, `s.code_points()`) and `core.task` (`Panic`, for `supervised spawn`). `core.mem` is raw memory (`Ptr`, `raw_alloc`, `load_i64`, `store_u8`, `atomic_add_i64`, ..., on machine integers), what the runtime is written in: only core's own modules can use it (anywhere else, `Ptr` and its functions are errors). `core.values` reads a compiled value back from memory, read-only, on top of core.mem: `Raw` (a value's address, as compiled code hands it over) with `r.word(i)` (its 64-bit slot `i`: a block's tag and fields, a list's header), `r.at(i)` (slot `i` as a value of its own) and `r.byte(k)`; core's modules, and a package whose strata.toml says `read = true` under `[values]` (the compiler, which runs compile-time code compiled and reads its value), can name `Raw` (anywhere else it is an error, once per definition), and `verify` never runs a function that takes one. `core.rt` is the runtime written in Strata: the allocator and reference counting (`strata_alloc`, `strata_dup`, `strata_release`, `strata_free`) and every `strata_...` entry point, calling the topic modules `core.str` (strings), `core.int` (integers), `core.list` (lists), `core.fmt` (format specs), `core.float` (floats), `core.gen` (generated values), `core.fault` (the call stack and faults) and `core.run` (tests' and fuzz cases' runs), which only it uses (`from core.str use ...`); nothing in these modules may allocate (the checker refuses lists, records and closures made at run time, `Int` arithmetic, and calls to anything but the runtime's functions, core.mem's and the integer conversions). `strata --file core test` runs core's own tests. What the compiler itself provides is declared with `builtin`, which only `core` may use: a type with its parameters (`builtin type Dict[K, V]`) and a function's signature, with `requires` where it fails on some arguments, so a builtin's precondition is a contract like any other, and one without `requires` always returns:

```rust
/// `xs[i]`: element `i`, from 0.
builtin fn at[A](xs: List[A], i: Int) -> A
  requires 0 <= i && i < len(xs)

/// The string of one character, code point `c` (not a surrogate).
builtin fn chr(c: Int) -> String
  requires 0 <= c && c <= 1114111 && !(55296 <= c && c <= 57343)
```

A name may have several signatures (`len` of a list, a dict or a set): the first whose parameters fit the arguments is called. `strata --file core view builtins` shows them all (`strata builtins` lists them in short); `strata --file core/ edit MODULE < text` stores a module of core as written (its names are global, nobody's module's), and `strata --file core check` checks the core strata is built with. Not yet contracts: `matches` with a pattern that isn't a regular expression, and a channel used after it ended.

## Compiling

`strata build` compiles a program to an executable through LLVM: compiler/codegen writes LLVM IR as text, `compiler/c/ir.c` builds it in LLVM (linked into `strata`) through LLVM's C API (LLVM's own reader of IR text only for what it doesn't know: it is several times slower), LLVM compiles it to objects (at -O0 with fast instruction selection), and lld links them with the runtime and std's precompiled library. The IR is cut into parts (runs of whole functions, each with copies of the constants it uses and, optimized, of the small functions it calls, to inline), compiled in parallel, one thread a core, and each part's object is kept in the cache (`objects/`, under the hash of its text), so after an edit only the parts it changed are compiled again; the program's IR is kept too (`ir/`, under the bytes of every file it is made of), and so is what `verify` proved as codegen reads it (`proofs-lines/`), so building what didn't change only links; a package with C of its own (`[native]`) keeps its C objects and its linked executable (one for each output path, under the link's arguments and the size and time of each file they name), so building it again unchanged only copies it. The objects are linked in the parts' order: the same program makes the same bytes. `--emit-llvm` prints the IR instead. A program compiler/codegen can't compile yet is an error that says why.

Programs are compiled unoptimized (`-O0`), which is fastest to build; `--release` compiles at `-O2` and merges the runtime into the executable (`-flto`). `run` and `test` take `--release` too. Compile-time code and the probes that confirm counterexamples are always unoptimized (they run once), `verify`'s fuzzing always optimized (its cases run many times), and std's precompiled library is built once at `-O2`.

The runtime is C (`runtime/runtime.c`) but for `core.rt` and its topic modules, written in Strata: the memory allocator (`strata_alloc`, `strata_dup`, `strata_release`, `strata_free`), `strata_unique`, the string, integer, list, format and float functions, the generators of values and a fault's call stack as text (`core.str`, `core.int`, `core.list`, `core.fmt`, `core.float`, `core.gen`, `core.fault`). `strata build-core` compiles it to LLVM IR with the C runtime's names, every executable links it, and strata itself is built in two stages to use it (`tools/bootstrap.sh`, see `core/rt.strata` in [the source layout](#source-layout)). `build` first verifies what changed since it was last verified (`--no-verify` doesn't), and the checks proven are left out of the program (`--all-checks` keeps them; see [verification](verification.md#what-is-proven-isnt-checked-again)).

A compiled program behaves as `strata run`: the same output, and contracts are checked at run time with the same fault messages (refinements of parameters, results, annotated bindings, declared variables and new values, `requires`, `ensures`, `assert`), exiting with 101. The language compiles (there is no interpreter), but for a few methods called on a value of a trait type (one taking `Self` inside another type, such as `List[Self]`, or type parameters together with `Self` or `mut`), which are refused saying so. In particular:

- `Int`, which never overflows: one in [-2^62, 2^62) is a machine integer, and arithmetic on it stays inline; any other is a big integer in the runtime (kept in the 64-bit values outside that range, so comparing a small and a big integer needs no call). `Float`, `Bool`, `String`, `()`, and refinements of them;
- records, variants (`Option`, `Result` and your own), tuples, `distinct` types, unions of any types; field access, `{ ..e, f: x }`, assigning a field (`x.a.b = e`), `is`, `==` on any of them, and printing them as code (`Debug` / `Display`);
- generic functions and types (each compiled once per set of type arguments), a type's own methods (`impl Item { ... }`), and traits: implementations chosen from the type where the call is compiled (default methods, supertraits, generic traits and implementations, static methods like `T.empty()`, a variant's own implementation chosen by its tag), with the trait's `requires` and `ensures` on every implementation;
- lists: literals, `+`, list patterns (`[x, ..rest]`), `for` over a list, `xs[i]` and slices (`xs[1..]`), and the list built-ins (`len`, `get`, `at`, `slice`, `push`, `take`, `drop`, `range`, `map`, `filter`, `fold`, `all`, `any`, `find`, `count`, `contains`, `reverse`, `sort`, `sort_by`, `zip`, `enumerate`, `sum`, `join`), most of them written in Strata (`runtime/prelude.strata`);
- dictionaries and sets: literals (`Dict { "a": 1 }`, `Set { 1, 2 }`, typed empty ones), `dict`, `set`, `insert`, `remove`, `get`, `contains`, `keys`, `values`, `items`, `map_values`, `to_list`, `union`, `intersection`, `difference`, `len`, `for` over them (a dictionary gives `(key, value)` pairs), `==`, printing (`Debug` / `Display`), and the refinements of their elements, keys and values. Each is a hash table, runtime.c's `strata_tbl_…`: a block laid out as the tuple of its entries (a set's elements, a dictionary's `(key, value)` pairs, in the order they came in, a removal closing the gap) and an index (open addressing, none for up to 8 entries), searched with functions codegen makes for the key type (`@"tbl.hash:T"` over `@"hash:T"`, the structural hash, and `@"tbl.cmp:T"` over the order); `for`, `len`, `items` and printing are the entries list's, `==` compares contents, and the order of two tables is that of their entries sorted. `compiler/eval` keeps a table's entries the same way (no hashing needed: the order depends only on what was done), so it prints them as compiled code does;
- strings: `+`, comparisons, a string's units (`bytes()`, `code_points()`, `graphemes()`) and positions as byte offsets (`byte_len`, `byte_slice`, `index_of`), and the string built-ins (`split`, `lines`, `trim`, `contains`, `starts_with`, `ends_with`, `replace`, `repeat`, `reverse`, `chars`, `to_upper`, `to_lower`, `is_digit`, `is_alpha`, `is_space`, `ord`, `chr`, `parse_int`, `parse_float`); most of them are Strata in the prelude over `byte_len` / `byte_at` / `byte_slice`, the rest (`trim`, case mappings, the `is_` tests, parsing numbers) C in the runtime, case mappings and `is_alpha` from tables made from Rust's;
- iterators (`for` over any `Iterator`, lazy `map` / `filter`, `iter()`), tasks (`scope`, `spawn`, `await`, a thread per task), channels and `select`, written `invariant`s (checked at the loop's head), and `extern c` calls;
- lambdas and closures, named functions as values (`filter(is_prime)`), functions returning functions;
- functions and recursion, bindings (`x := e`, with patterns, `let x: T = e`), `mut` variables and assignment (`=`, `+=`, …), `if`, `match` with every pattern, `while`, `loop`, `for`, `break`, `continue`, `return`, `assert`, `!`, `?`, `except`;
- f-strings with format specs (`{x:.2}`, `{n:>5}`, `{n:05}`, `{s:*^9}`), and `print`, `to_string`, `abs`, `min`, `max`, `float`, `floor`, `ceil`, `round`, `sqrt`;
- `mut` parameters and receivers (`restock(mut line.qty, 5)`, `mut console.print(s)`): the function changes the caller's variable in place, and the variable's declared type is checked after the call;
- capabilities: `main` can ask for `Console` (std.io) and capabilities such as `Disk`, `Process` and `Codebase` (std.fs, std.process, std.code), and gets the terminal, the disk, the process and the codebase in the current folder, as with `strata run` (the program's arguments too). `Codebase`'s snapshot is built by strata and written into the program's memory, so a program built with `strata build` has none (it faults saying so). A parameter whose type is a trait (`console: Console`) is compiled once per implementation passed to it, as the language defines it (`console: C` for some `C: Console`): the real console and a `Recorder` in a test each get their own. A trait used as the type of a field, a list element or a `let` (`{ console: Console }`, `List[Shape]`) holds any implementation: the value carries its implementation's table of methods, and calls go through it;
- options: `main` can ask for a record that derives `CommandLine` (std.cli); the compiled program reads it with the same `from_args`, so `--help` and the messages for bad arguments are `strata run`'s (exit code 0 after the help, 2 after an error). The usage line names the executable as it was started (`strata build` names it after the package, as `strata run` does);
- `main` returns `()`, an exit code, or a `Result` of either.

A fault prints the call stack as `strata run` does (`    stack: main -> inner -> half`), and running out of stack is a fault (`fault (Limit): stack overflow (recursion too deep)`), not a crash. There is no other limit: loops run as long as they run, and a recursion as deep as the stack allows; the `stack:` line shows a recursion as one entry (`main -> down (95846 times)`).

`matches(s, re)` is `std.regex`'s, compiled. A literal pattern's matcher (`std.regex.matcher`: a DFA, or the Pike VM's program when the pattern asserts more than `^` and `$`) is made while compiling, as compile-time code is (cached), and is data in the program. A pattern built at run time is matched by `std.regex` (its parser and Pike VM, written in Strata and precompiled with std), in a built program too; a bad one faults with `std.regex`'s message (`bad regex: unclosed group (at character 11)`). Memory is reference-counted: a value is freed as soon as nothing holds it. While tasks run, counts change atomically, and each thread takes small objects from free lists of its own (refilled from the shared ones 64 at a time, given back when the thread ends) and opens arenas of its own; a list extended in place past its end takes the slot with an atomic add, so two threads sharing a buffer can't both take it. A program can ask (core.rt's `strata_memory_keep_shared`, which the compiler sets while its workers run) that an object held more than once that a thread holds once more while tasks run be kept for good instead (never counted again nor freed), so threads reading the same tables don't fight over their counts' cache lines. With `STRATA_MEMORY` set, a compiled program reports how many objects it allocated and freed when it exits (`memory: 128 allocated, 128 freed, 0 live`); with `STRATA_MEMORY=check` it also keeps freed memory aside, stops on any use of a freed object (`memory: drop of a freed object`), and lists the objects still alive at the end (the tests of `strata build` run every program this way).

### The JIT

`strata verify` runs only compiled code (`--jit` says why a function's fuzzer couldn't be compiled, which is then skipped). Fuzzing: a driver per function generates its arguments (the generators `mock` uses), records them for a counterexample, and calls it, all in one module compiled once; a trait method of an implementation, and a law, are fuzzed through a wrapper function (a law's ensures it holds). Loops and calls count steps, so a runaway case is a `Limit` fault (`too many steps`). The solver's counterexamples are confirmed by running them compiled (a probe binding the values to the parameters' types, then calling the function), and so are literal arguments that break a refinement (`attr("onclick", …)`), an error before anything runs. Probes, like compile-time code, are compiled without optimization: they run once.

`strata test` compiles the tests the same way: each `test` block is a function, a fault ends the test instead of the process, and what a test prints is kept for the report (`strata test --emit-llvm` prints the tests' IR). A test that can't be compiled yet fails, saying why; the others run. Only the project's own tests run, those in its files (the package's, or the script's): what it imports (std, and dependencies once they are fetched) is compiled, verified and tested on its own (std with `strata --file std test`), so its tests aren't run again. `strata test --with-deps` runs them too.

`strata run` compiles the same IR in memory with LLVM's libraries and runs it (the JIT: compiler/codegen's IR, run by the compiler's own JIT, with std's precompiled library and a package's `[native]` C loaded), so a program runs at native speed without a build step (`fib(32)`: 26 ms, compilation included). What can't be compiled yet is an error that says why (there is no interpreter). `strata run f [ARGS]` calls one function, compiled: its arguments, written as code (`'"abc", 3'`), go into a function that calls it, checked with the program, and its result is printed as code (the compiled call hands over its `debug` text), and `--trace` has compiled code print each call and return. Compile-time code runs on the JIT too: in a `derive`, and `comptime e` anywhere else, whose value is computed while compiling and written into the program as a constant (`re := comptime parse("[a-z]+")` never calls `parse` when the program runs). `e` may use definitions, not the variables around it. In the compiler written in Strata (`compiler codegen`, which `build` uses), `comptime e` is compiled by compiler/codegen and run by the compiler's own JIT in its process, within 5,000,000 steps, and its value is read back from memory by its type (codegen's `read_back`, core.values) and written in with that type; what codegen can't compile yet, and the small pieces of a derive's code, run on compiler/eval.

Both ways share one code generator (the IR as text, which `compiler/c/ir.c` builds in LLVM for the JIT too) and one runtime (`runtime/runtime.c`, linked into `strata` for the JIT, and with the program by `strata build`; a release ships it precompiled).

## The compiler in Strata (`compiler/`)

The `strata` command is the `compiler/` package: an ordinary package (its modules named by their paths: `lex`, `parse`, …), a program rather than a library, and not part of std. `tools/bootstrap.sh` builds it with a `strata` built before (a release, or `STRATA_SEED`), then with itself, until the build is a fixed point (`target/strata`). Its `main` dispatches the command line (`compiler/driver` reads it); the steps it runs on files keep the names the tests use (`lex FILE`, `codegen FILE`, `jit`, `object`, `link`, …).

### Module by module

The **compiler written in Strata** is the `compiler/` package: a program, not part of std (programs don't import it). Its `main` runs one step of the front end on files (`strata --file compiler run -- lex FILE`, `parse`, `stored`, `check`, `eval`, …: see `compiler/main.strata`). Its modules:
